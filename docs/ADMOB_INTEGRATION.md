# AdMob 연동 (Outtap)

## 1. 구성

| 부분 | 위치 | 내용 |
|---|---|---|
| Android 플러그인 | `android_plugin/` → `addons/outtap_ads/bin/outtap_ads-{debug,release}.aar` | Godot v2 Android 플러그인(Java, `OuttapAdsPlugin`). 배너·전면·보상형과 UMP 동의를 처리 |
| 내보내기 플러그인 | `addons/outtap_ads/export_plugin.gd` | Gradle 의존성 `play-services-ads:25.5.0`, `user-messaging-platform:4.0.0` 추가, 매니페스트 App ID를 `AdsConfig`에서 기록 |
| 설정 | `scripts/ads/ads_config.gd` | 디버그(그리고 `ads_test` 기능 플래그)에는 Google 공식 **Android 테스트 ID**. 출시 빌드는 실제 ID가 비어 있거나 테스트 ID면 내보내기와 실행을 거부(테스트 ID로 대체하지 않음) |
| 상태 기계 | `scripts/ads/ads_manager.gd`, `ad_slot.gd`, `ad_policy.gd` | 형식별 슬롯 EMPTY/LOADING/READY/SHOWING/BACKOFF/BLOCKED, 요청 ID로 늦은 콜백 무시, 오류 코드 분류(0/1/2/3/8/9/10/11), 백오프 15→30→60→120초 |
| 진단 | `scenes/debug/ads_diagnostics.gd` | 디버그/QA 빌드의 설정 화면에서만 보이는 광고 상태·로그 화면 |

**디버그 테스트 ID** (공식 문서 기준, iOS ID와 섞지 않음):

- App: `ca-app-pub-3940256099942544~3347511713`
- Banner: `ca-app-pub-3940256099942544/9214589741`
- Interstitial: `ca-app-pub-3940256099942544/1033173712`
- Rewarded: `ca-app-pub-3940256099942544/5224354917`

2026-10-09에 만든 `build/outtap-debug.apk`의 매니페스트에서 App ID가 위 테스트 값임을 `aapt2`로 확인했습니다. dex 안에 `OuttapAdsPlugin`, Mobile Ads, UMP 클래스가 있는 것도 확인했습니다.

## 2. 동의(UMP)

- 앱을 시작하면 UMP 동의 정보를 갱신하고, 필요하면 동의 화면을 띄웁니다.
- `canRequestAds`가 참이 된 뒤에만 SDK를 **한 번** 초기화하고 광고를 요청합니다. 동의 과정이 실패해도 게임은 진행됩니다.
- 설정의 "광고 개인정보 선택" 버튼은 UMP가 개인정보 옵션을 요구하는 지역에서만 보입니다.

## 3. 노출 규칙 (`AdPolicy.DEFAULTS`)

| 광고 | 언제 | 막는 조건 |
|---|---|---|
| 배너 | 홈·스테이지 목록 아래(내용을 가리지 않게 높이를 비워 둠) | 게임 화면에는 없음 |
| 전면 | ① 클리어 카드에서 "다음 스테이지"를 누를 때 ② 실패 카드에서 "다시 시작"을 누를 때(2026-10-11 사용자 결정). 실패 카드 자체와 "체크포인트부터 다시"에는 나오지 않습니다 | 1~5스테이지, 설치 후 실제 플레이 180초 이전, 직전 전면 광고 이후 새 클리어 3개 미만(①만), 직전 전면 광고 이후 실제 플레이 150초 미만, 앱 실행당 4회, **다음 판이 HARD일 때(`HARD_AHEAD`, QA 모드에서도 적용)** |
| 보상형 | 힌트 추가(+1) / 하트 1개로 이어하기(판당 1회) | 플레이어가 확인 창에서 직접 선택할 때만 |

- **플레이 중·클리어 연출 중에는 전면 광고가 절대 나오지 않습니다.** 전면 광고를 부를 수 있는 자리는 클리어 카드의 "다음" 버튼과, 하트를 모두 잃은 직후(판이 이미 끝난 뒤) 두 곳뿐입니다.
- 전면 광고 뒤의 "다음 판으로" 처리는 정확히 한 번만 실행됩니다. 광고가 없거나 실패해도 바로 이어집니다.
- **보상은 SDK의 실제 보상 지급 콜백에서만** 줍니다. 닫힘이나 노출은 근거가 아닙니다.
  - 늦게 오는 지급 콜백을 위해 닫힌 뒤 1.5초를 기다립니다.
  - 거래 ID 장부로 중복 지급을 막습니다.
  - 보상은 그 광고를 본 시도(attempt)에만 적용합니다.
- 전체 화면 잠금은 실제로 활동이 다시 돌아온 증거가 있을 때만 풉니다.
- 광고가 표시되는 동안 오디오는 일시정지하고, 게임 시계와 입력도 멈춥니다.

## 4. 테스트

- `tests/ads_tests.gd`(가짜 공급자로 오류 주입): **54 checks, 0 failures**(2026-10-09). 우리 상태 처리만 검증합니다. 실제 SDK 동작의 증거는 아닙니다.
- `tests/arrow_flow_tests.gd`:
  - 1~5스테이지 전면 광고 생략, HARD 직전 생략(`HARD_AHEAD`)을 확인합니다.
  - 데스크톱에서는 공급자가 없으므로 `UNSUPPORTED_PLATFORM`으로 생략됩니다.
- **실기기 확인:** 같은 날 앞선 작업에서 Galaxy S24+(SM-S926N, Android 16)에 디버그 빌드를 설치했고, Google 테스트 광고가 실제로 로드되는 것을 확인했습니다.
  - 그 확인은 이번 개편(화살표 규칙·HARD·리그) **이전 빌드**에서 했습니다.
  - 이번 라운드의 새 APK는 아직 기기에 설치하지 않았습니다. 설치와 확인은 사용자 승인 후 진행합니다.
- 테스트 광고를 실제로 누르게 하지 않습니다. 실제 광고(운영 ID)를 테스트 목적으로 누르면 안 됩니다.

## 5. 출시 전 할 일

1. AdMob 콘솔에서 앱과 광고 단위를 만들고 `AdsConfig.PRODUCTION_IDS`를 채웁니다.
2. `python3 tools/export_release.py`로 출시 빌드를 만듭니다(운영 ID 검사 포함).
3. Play Console의 대상 연령 선언과 `AdsConfig.REQUEST`(일반 연령, PG)가 일치하는지 확인합니다.
4. 실기기에서 동의 화면, 배너·전면·보상형 표시, 보상 지급, 백그라운드 복귀를 다시 확인합니다.
