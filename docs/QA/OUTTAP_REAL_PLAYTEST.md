## D. UI / 그래픽 평가

### 첫 실행과 첫 3레벨

[첫 화면](screenshots/001_first_launch.png)은 작은 캐릭터 아이콘과 큰 이야기 카드다. 한국어는 읽기 쉽고 버튼 크기도 충분하다. 첫 실행에서 이야기 카드 3장을 지나야 퍼즐을 조작한다. 게임 규칙 자체는 [1레벨](screenshots/002_level01.png)의 “머리 방향으로 탈출” 문구와 세 개의 큰 경로로 빠르게 이해된다. 첫 30초를 순수 신규 사용자로 계측하지 못했으므로 5초 이해율·기동 속도는 주장하지 않는다.

2레벨의 길을 막는 긴 경로를 제거한 뒤 다른 길이 열리는 변화는 명확했다. 기본 제거 애니메이션은 관찰한 범위에서 경로가 사라지는 결과를 읽기 쉬웠다. 만족스러운 소리까지 확인한 것은 아니다.

첫 성공 뒤 출석 등불 카드, 이어 별·복원·리그·다음 스테이지 줄이 많은 [클리어 카드](screenshots/003_level01_clear.png)가 나타난다. 퍼즐을 계속하고 싶은 순간에 정보량이 늘어난다. 보상은 눈에 보이지만 초반 퍼즐 흐름은 느려진다.

### 판독과 조작

[3레벨 초기 화면](screenshots/005_level03.png)은 경로가 좌우에 잘렸다. [전체 보기](screenshots/006_level03_fit.png)에서는 모든 경로가 보이지만 화살표 머리가 작아진다. 4레벨도 같은 전환을 사용했다. 이는 화면 결함이라기보다 **초기 확대 정책의 UX 문제**다. 후속 소스 확인: `START_CELL = 30`, fitted cell이 더 작으면 보드 중앙을 확대해서 시작한다. 큰 판 전체를 먼저 보여주지 않는다.

[5 HARD](screenshots/010_level05_hard_start.png)의 전체 보기 셀은 로그 기준 15 logical px였다. 93개 경로가 단색으로 밀집해 머리와 단순 꺾임을 혼동했다. 확대 후 힌트의 머리를 확인하는 것은 도움이 됐다. 드래그로 보드를 이동할 수 있었다. 드래그 직후 하트가 깎이는 현상은 해당 동작에서 관찰하지 않았다. 실제 손가락 터치 정확도와 핀치는 확인하지 않았다.

1레벨의 긴 몸체 선택은 성공했다. 3레벨의 일부 연속 입력 뒤 마지막 화살표가 남아 재선택이 필요했다. 좌표·애니메이션·배치 입력 타이밍 영향이 있어 입력 유실 버그로 확정하지 않는다. 실패 카드 이후 입력이 버튼에 전달된 일도 자동화의 한계로 별도 기록한다.

배경은 단색 빈 화면보다 완성도가 있다. Night Harbor의 달·등대·별, Soft Morning의 구름은 보드를 돋보이게 한다. 다만 기본 단색 선은 밀집 퍼즐에서 경로 구분을 돕는 정보가 부족하다. “업무용 앱”으로 보일 정도는 아니지만, 촘촘한 보드 자체는 얇은 선 도식처럼 느껴진다.

## E. 사운드 / BGM / 음성

**실제 청취 평가 미완료.** 음악이 매력적인지, 충돌음이 거슬리는지, 음성이 자연스러운지, 장시간 루프가 피곤한지, 연속음이 왜곡되는지 판단하지 않는다.

확인한 것은 UI의 독립 토글과 구현 구조다. AudioManager는 Music / SFX / Voice 버스, 효과음 풀, 짧은 재트리거 억제, 음성 동시 재생 방지, 음악 크로스페이드·덕킹을 사용한다. 한국어·영어 음성 및 다른 언어의 효과음 대체 안내가 설정에 보였다. 이는 실제 출력 성공이나 좋은 믹싱의 증거가 아니다.

Mac에서 실제 진동을 느끼지 않았다. HapticManager가 Android / iOS에서만 진동 API를 호출하는 구조를 확인했지만 Android 진동·세기·패턴은 미검증이다.

## F. 게임성 및 첫 HARD 집중 분석

**좋았던 구간: 2레벨.** 한 경로를 빼면 가려진 다음 경로가 열리는 과정이 직관적이다. 처음으로 차단 관계를 추적한 것은 2레벨이다. 1레벨은 규칙 학습이다. 4레벨의 금색 수집과 배경 해금도 작은 보상으로 읽힌다.

**반복·답답함이 처음 커진 구간: 3레벨의 화면 맞춤 전환.** 제거 자체가 지루해서라기보다 판독 상태를 관리해야 하는 일이 먼저 늘었다. 5에서는 “어떤 출구가 열려 있는가”를 생각하는 시간과 작은 머리의 방향을 알아보는 시간이 섞였다. 실패할수록 순수한 도전보다 다시 많은 경로를 제거해야 하는 비용이 부각됐다.

이 게임을 관찰형 차단 해제 퍼즐로 평가한다. 성공적인 제거가 다른 선택을 더 나쁘게 만드는 장면은 없었다. 안전하게 열려 있는 경로는 여러 개 중 어느 것을 먼저 빼도 계속 공간이 열린다. 따라서 장기 전략·필수 최적 순서가 풍부하다고 평가하지 않는다. 세 하트는 실제 신중함을 만들었지만 작은 표식 오독에도 같은 대가가 붙는다.

| 생각하며 길을 찾는가 | 차단 관계 관찰은 필요. 전략적 악수 선택은 확인 못함 |
| 제거 후 새 길이 열리는가 | 첫 시도 34개 제거 동안 경험함 |
| 확대·이동이 편리한가 | 더블탭·전체 보기·드래그는 동작. 상태 전환과 잘림은 부담 |
| 화살표 선택과 이동이 충돌하는가 | 단일 드래그에서 충돌 미관찰. 입력 연속 처리에는 오염 있음 |
| 너무 작은가 | 15px 셀 전체 보기에서는 그렇다고 판단 |
| 재미있는 어려움인가 | 초반 길 열림은 재미. 이번 제한된 시도 후반에는 판독 부담 우세 |
| 실패 원인은 이해되는가 | 실패 카드가 “머리 앞이 판 끝까지 비어 있어야 한다”고 설명. 전체 맞춤에서 어느 선이 막았는지 재추적은 어려움 |
| 너무 쉽게 클리어하는가 | 클리어하지 못했으므로 해당하지 않음 |
| HARD 성공이 특별한가 | 미클리어, 평가 불가 |
| 성공 후 다음 판 의향 | 미클리어, 평가 불가 |
| 실제 클리어 시간 | 없음. 5:24.226 실패 + 1:30.480 오염된 재시도 |

처음 지루함보다 조작 부담을 느낀 것은 3레벨, 종료/삭제를 고려한 것은 5레벨의 실패 후 재도전 비용이다. BGM 때문에 지루해진 시점은 청취하지 않았으므로 없다. 후반 배치 반복·쉬어가기 곡선은 플레이하지 않아 판단하지 않는다.

## G. 광고 UX / Android 검증

[광고 진단](screenshots/014_ads_unsupported.png)은 test mode / provider unsupported / SDK not_started / UMP 미진행. 게임 로그에서도 두 실패 광고 기회가 `UNSUPPORTED_PLATFORM`으로 생략됐다. 실제 광고 노출 0, 보상 지급 검증 0. 실패 UI와 홈 이동은 멈추지 않았다.

정적 광고 정책: 1~5 전면광고 제외, 초기 play 180초 보호, 새 클리어 3개 간격, fullscreen 간격 150초, 세션 전면광고 최대 4회, 다음 레벨이 HARD면 생략. 성공 후 다음 판 전환 및 실패 전환이 기회다. 실패에도 광고 기회가 있다는 점은 Android에서 별도 평가해야 한다. 코드상 보호 조건을 실제 광고 경험과 혼동하지 않는다.

**출시 차단 설정:** `scripts/ads/ads_config.gd`의 PRODUCTION_IDS(app_id / banner / interstitial / rewarded)가 모두 비어 있다. AdMob 수익화를 목표로 한 현재 상태는 출시 설정 완료 상태가 아니다. 실제 릴리스 빌드가 실패하는지 빌드를 실행해 확인한 것은 아니다.

Android 설정은 package `com.namslab.outtap`, min SDK 24 / target 36, immersive 및 edge-to-edge, 진동·인터넷 권한이다. APK 설치, 터치, 핀치, 화면 잘림, 동의 폼, 광고 종류별 종료 복귀, 시스템 오디오, 백그라운드, 장시간 FPS는 모두 미검증이다. 기존 history의 다른 버전 실기기 성공 기록을 이번 버전 검증으로 사용하지 않았다.

## H. 경쟁작 대비 평가

Amaze GO!를 별도 실행하거나 참고 영상을 확인하지 않았다. 사용자 요청에 적힌 비교 기준만 사용했다.

| 기준 | Outtap에서 확인한 점 |
|---|---|
| 초반 학습 | 큰 세 경로와 한국어 안내는 쉬움. 이야기 카드가 앞섬 |
| 이른 HARD 전환 | 5에서 명확하게 증가. 단, 재미 있는 난이도인지보다 판독 부담이 문제 |
| 긴 경로 / 탐색 | 풍부함. 제거 후 열린 길을 찾는 경험 있음 |
| 애니메이션 / 성공 | 기본 탈출 결과는 명확함. HARD 성공은 미검증 |
| UI 집중 | 퍼즐 중심 화면. 클리어 보조 정보와 확대 상태 관리가 흐름을 끊음 |
| 사운드 | 비교 불가: 실제 청취 없음 |
| 반복 동기 | 복원·테마·개인 리그 보상 확인. 후반 동기 유지 미검증 |
| 실패 | 규칙 문구는 설명되나 작은 표식 오독 부담과 재시작 비용이 큼 |

“인기작과 경쟁할 만큼 좋다”는 결론을 낼 근거는 부족하다. 강점은 차단 해제의 즉각적인 시각 변화와 초반 복원 보상이다. 부족한 점은 복잡한 판을 읽고 조작하는 UX의 균형이다.

## I. KEEP / DELETE 최종 판단

**DELETE — 초반 실제 경험에 한정한 Codex 판단.** 첫 3레벨 시점에서는 계속 플레이할 의향이 있었지만, 첫 HARD 실패 뒤에는 읽기 비용과 재시작 비용이 앞섰다. 실패 데이터 일부는 도구 오염이므로 일반 사용자가 똑같이 실패하거나 삭제한다고 추정하지 않는다.

| 시점 | 판단 |
|---|---|
| A: 첫 3레벨 | 계속할 의향 있음. 2의 연쇄 해제는 재미 |
| B: 첫 HARD 클리어 | 미달. 클리어 후 의향 평가 불가 |
| C / D: 10 / 20 이후 | 미플레이, 평가 불가 |
| E: 50 이후 | 현재 캠페인에 없음 |
| F: 최종 20 | 미플레이, 평가 불가 |

1. 설치 이유: 짧은 시간에 관찰하고 판을 비우는 캐주얼 퍼즐이라는 약속.
2. 첫 5분: 재미 있는 핵심은 확인했다. 인간의 5분 세션으로 계측한 결과는 아니다.
3. 20분 이후: 순수 플레이 합은 17:06이고 도구 체류 시간은 더 길다. 현재 범위에서는 계속할 의향이 낮아졌다. 인간 20분 실험은 아니다.
4. 다음 날 이유: 복원·출석·개인 리그가 있다. 실제 다음 날 재접속/D1·D7은 측정하지 않았다.
5. 삭제 고민: 5레벨에서 작은 머리를 확인하려 확대/맞춤을 반복하고 실패한 순간.
6. 가장 큰 장점: 한 화살표를 제거하면 차단 관계가 풀리고 판이 정리되는 즉각적 변화.
7. 유지 이유가 부족한 원인: 관찰의 재미보다 판독과 재시작 비용이 커졌다.
8. 다른 유명 퍼즐로 옮길 가능성: 더 읽기 쉬운 보드를 찾고 싶다. 특정 경쟁작을 더 좋다고 검증한 것은 아니다.
9. 무료여도 가치: 짧게 해볼 가치는 있지만 현재 경험만으로 계속 설치할 이유는 부족하다.
10. 광고까지 나오면: 이 경험 위에 기다림이 더해지면 유지 의향은 더 낮아질 것으로 예상한다. 실제 광고 청취/시청 후 판단이 아니다.

**“내가 실제 사용자라면 Outtap을 DELETE 하겠다. 가장 결정적인 이유는 첫 HARD에서 길을 푸는 재미보다 작은 경로를 판독하고 실패 후 다시 진행하는 부담이 커졌기 때문이다.”** 이 문장은 Codex의 제한된 GUI 경험을 바탕으로 한 사용자 관점 가정이며 실제 사람의 설문 결과가 아니다.

## J. 개선 우선순위

자세한 원인 가설·효과·재검증은 [개선 백로그](IMPROVEMENT_BACKLOG.md)에 별도로 저장했다. 이번 감사에서는 기능을 고치지 않았다.

가장 먼저 할 다섯 가지:

1. **P1:** 큰 보드를 전체 개관 → 유효 탐색 영역 확대 흐름으로 바꾸고 전체 맞춤의 머리 판독성을 개선.
2. **P1:** 첫 HARD의 밀도/화살표 수와 하트 3개 조합을 실제 신규 사용자로 조정. 이번 93개를 무조건 축소하라는 뜻이 아니라 읽기 부담과 해결 재미를 분리해 확인.
3. **P1:** 충돌 뒤 어떤 경로가 막았는지 지속해서 읽을 수 있는 피드백 제공. 작은 표식 오독의 원인을 사용자가 이해하도록 함.
4. **P2:** 첫 성공 뒤 출석·리그·복원 카드의 정보량과 탭 수 축소.
5. **출시 게이트:** Android 터치·핀치·청취·광고 복귀 실검증 및 production 광고 설정 완료. 검증 공백을 그래픽 장식으로 대체하지 않음.

P0 게임 버그는 입증하지 못했다. 별도 P1 출시 준비 항목으로 광고 설정과 실기기 검증이 남는다. P2는 실패 홈 문구, timer의 이야기 대기 포함, 초반 보상 흐름. P3 추가 챕터·스킨·새 모드는 핵심 판독 UX 이후 검토한다.
