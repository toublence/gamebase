## 2. 생성기 (`ArrowGenerator.build_shaped`, `arrow-gen-2-shaped`)

1. **실루엣 마스크:** `Silhouettes.mask(shape, w, h)`로 그림 칸을 정합니다. 기본 도형을 조합한 뒤, 이웃이 부족한 칸과 고립 영역을 정리합니다.
2. **긴 것부터 채우기:** 길이 대역(예: `[[8,14,0.55],[4,7,0.35],[2,3,0.1]]`)을 긴 것부터 비중만큼 채웁니다. 모양 모드는 직선·L·U·계단·갈고리·자유 굽힘입니다. 남은 칸은 2~3칸 화살표로 채웁니다(채움 93%).
3. **방향 정하기:** 다른 화살표에 막히는 끝을 머리로 우선 고르고, 같으면 그림 안쪽을 향하는 끝을 고릅니다. 자기 몸을 향하는 머리는 만들지 않습니다.
4. **교착 해소(`repair_until_solvable`):** 실제 규칙으로 벗겨 보다 막히면, 뒤집어서 빠질 수 있는 화살표를 뒤집습니다. 이때 전체 판에서는 여전히 막혀 있는 "숨은" 뒤집기를 우선합니다. 그래도 안 되면 그 화살표를 지웁니다(드묾).
5. **HARD 조이기(`tighten`):** 칸 점유는 그대로 두고, 처음 풀린 화살표 수를 줄이는 이동만 받아들입니다. 이동마다 정확한 풀이기로 풀 수 있는지 다시 확인합니다.
   - 뒤집기: 머리를 그림 안쪽으로 돌립니다.
   - 잇기: 이웃 화살표와 끝끼리 이어 하나의 긴 화살표로 만듭니다(최대 길이 제한).
   - 칸 넘기기: 이웃과 끝 칸을 주고받거나, 빈 그림 칸으로 머리를 늘입니다.
   - 쌍 뒤집기: 뒤집기만으로 교착이 생기면 그 교착 안의 화살표 하나를 함께 뒤집습니다.
   - 사과 18×24 기준: 처음 풀린 화살표가 9~15개에서 5~8개로 줄었고, 판당 50ms 이내였습니다.
6. **빠른 풀이기(`ArrowSolver.stuck_ids` / `is_solvable`):** 레이 길이 합에 비례하는 시간으로 풀이 가능 여부를 판단합니다. 각 화살표 앞의 점유 칸 수를 세고, 칸이 비면 그 칸을 보던 화살표의 수를 줄입니다. 층별 벗기기(`peel`)와 답이 같은지 테스트합니다.

같은 시드는 언제나 같은 판을 만듭니다. 난수는 Mulberry32(`Prng`)이고, 엔진 난수를 쓰지 않습니다.

## 3. 난이도 지표 (`ArrowSolver.metrics`)

| 지표 | 의미 |
|---|---|
| n, cells, density | 화살표 수, 덮은 칸, 판 대비 밀도 |
| avg_len, len_std, max_len, short/medium/long | 길이 분포(≤3 / 4~7 / ≥8칸) |
| bends, max_bends, straight, multi_bend | 굽힘 총량과 분포 |
| initial_free | 처음 빠질 수 있는 화살표 수 |
| visible_free | 그중 출구가 그림 바깥 빈 공간으로만 나는 것(찾기 쉬운 시작점) |
| layers | 층별 벗기기의 층 수(연쇄 깊이) |
| keys, cascade, avg_open | 한 수로 2개 이상 길을 여는 "열쇠 이동" 수, 최대 연쇄, 평균 개방 |
| fanout | 한 화살표가 막고 있는 최대 수 |
| narrow, avg_choices | 선택지가 2개 이하인 구간 수, 평균 선택지 |
| far_blocks, contacts | 멀리서 막는 관계, 이웃 접촉 수 |
| est_seconds | 탐색 비용 추정(사람 측정 아님) |
| similar_prev | 직전 판과의 흐름 방향 유사도(대칭 8가지 중 최대, 0.45 초과 후보 제외) |

**후보 순위:** 연쇄 깊이 0.6 + 열쇠 이동 0.5 + 평균 길이 0.8 + 길이 편차 0.5 − 목표 시간과의 차이 0.05입니다(각 값에 곱하는 가중치). 이 순위로 상위 후보를 렌더링해 검토한 뒤 고정했습니다.

**단계별 통과 범위(요약):**
- **HARD:** 처음 풀림 2~5(5스테이지는 2~6), visible_free 1 이상, 층 12~13 이상, 긴 화살표 8~10개 이상, 예상 40~150초.
- **보통:** 처음 풀림 3~6, 층 7~16.
- **쉬어가기:** 처음 풀림 4~10, 층 3~8.

## 4. 빌드가 매번 하는 검증 (`tools/build_arrow_levels.gd build`)

- **구조:** 규칙 태그, 보드 크기(3~32 × 3~40), 칸 범위, 겹침, 연결성, 2칸 이상, 자기 몸을 향한 머리 금지.
- **풀이:** 정확한 벗기기로 풀 수 있는지 확인하고 풀이 순서를 저장합니다. 저장된 풀이를 실제 규칙으로 재생합니다.
- **실루엣:** 알 수 없는 모양이면 실패합니다. 화살표 칸이 실루엣 밖이면 실루엣을 넓히고 알립니다(현재 0건). 같은 실루엣이 반복되면 실패합니다.
- **기록:** 황금 화살표 선택, 지표, 내용 해시(sha256 16자리), 직전 판 유사도를 함께 저장합니다.
- **리듬(`rhythm_problems`):** 도전 판은 앞 도전 판보다 높고, 도전 판 다음 판은 75% 이하, 나머지는 앞 판보다 2% 이상 높아야 합니다(도전도 기준). 단계(grade)는 내려갈 수 없습니다.

## 5. 독립 검증 (`tools/validate_arrow_levels.py`)

게임 코드를 공유하지 않는 Python 재구현으로 다음을 확인합니다.

- 스키마·규칙 태그, 경로 구조, 머리 자기충돌, 내용 해시, 저장된 풀이 재생, 벗기기 풀이 가능, 지표의 화살표 수.
- 설계 규칙: 실루엣이 모든 화살표 칸을 덮는지, 황금 화살표 번호가 유효한지, 실루엣이 중복되지 않는지, **단계 판은 처음 풀린 화살표가 `max(6, 화살표의 8%)` 이하**인지, 1~4스테이지에 단계가 없는지.
- **리듬:** 예상 시간과 풀이 층을 Python으로 다시 계산해 도전도를 구하고, 도전 판·쉬어가기·상승 규칙을 확인합니다. 단계(색 묶음)가 내려가지 않는지도 봅니다.

**결과(2026-10-10, 라운드 6):** `All 20 arrow-path-2 levels pass the independent rule check.`

## 6. 게임 실행 중 보호

`Levels`(오토로드)는 처음 읽을 때 모든 판의 구조·해시·풀이 재생을 다시 확인합니다. 손상된 판은 앞의 유효한 판으로 대체하고 진단 로그에 남깁니다.

이어하기 저장은 규칙 태그와 내용 해시가 다르면 복원하지 않습니다. 그래서 판이 바뀐 업데이트 뒤에도 깨진 보드가 나오지 않습니다.

진행 epoch 3: 이번 재설계로 같은 스테이지 번호의 판이 바뀌었으므로, 이전 진행은 `previous_campaign`에 백업하고 스테이지 진행만 1부터 다시 시작합니다(한 번만). 보상 기록·플레이 시간·광고 카운터·장면·스킨·리그는 유지합니다.
